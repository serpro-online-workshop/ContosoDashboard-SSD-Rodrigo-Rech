# Data Model: Document Upload and Management

**Feature**: `001-document-upload-management`  
**Storage**: Existing EF Core `ApplicationDbContext` backed by SQLite

## Entities

### Document

Represents the current available file and its searchable metadata.

| Field | Type | Rules |
|---|---|---|
| `DocumentId` | integer | Primary key; generated by SQLite; stable application identifier. |
| `Title` | text | Required after trimming; maximum 255 characters. |
| `Description` | text, nullable | Maximum 2,000 characters. |
| `Category` | text | Required; one of `Project Documents`, `Team Resources`, `Personal Files`, `Reports`, `Presentations`, or `Other`. |
| `UploaderId` | integer | Required foreign key to `User`; ownership authority source. |
| `ProjectId` | integer, nullable | Optional foreign key to `Project`; required when the document is project-scoped. |
| `TaskId` | integer, nullable | Optional foreign key to `TaskItem`; a task association must use the task's project. |
| `OriginalFileName` | text | Metadata only; maximum 255 characters; never used as a storage path. |
| `FilePath` | text | Required private relative storage identity; generated by the service; unique; never accepts a user path. |
| `FileSize` | integer | Required positive byte count; maximum 26,214,400 bytes (25 MiB implementation limit). |
| `FileType` | text | Required content type; maximum 255 characters. |
| `UploadedAtUtc` | datetime | Required UTC timestamp. |
| `UpdatedAtUtc` | datetime | Required UTC timestamp; changes on metadata or file replacement. |
| `IsAvailable` | boolean | True only after validation, storage, and safety checks complete. |

The application may retain a non-available candidate only during an internal operation;
no rejected or incomplete candidate is returned by document queries. A failed first
upload creates no accessible `Document` row. A failed replacement leaves the existing
available row and file unchanged.

### DocumentTag

Represents one normalized user-supplied search tag.

| Field | Type | Rules |
|---|---|---|
| `DocumentTagId` | integer | Primary key. |
| `DocumentId` | integer | Required foreign key to `Document`; dependent rows are removed with the document. |
| `TagText` | text | Required after trimming; maximum 100 characters; normalized for duplicate comparison. |
| `CreatedAtUtc` | datetime | Required UTC timestamp. |

A unique constraint on `DocumentId` plus normalized `TagText` prevents duplicate tags on
one document while allowing the same tag on different documents.

### DocumentShare

Represents an explicit permission grant to one user or one department team.

| Field | Type | Rules |
|---|---|---|
| `DocumentShareId` | integer | Primary key. |
| `DocumentId` | integer | Required foreign key to `Document`. |
| `TargetUserId` | integer, nullable | Direct recipient; mutually exclusive with `TargetDepartment`. |
| `TargetDepartment` | text, nullable | Department team recipient; maximum 100 characters; mutually exclusive with `TargetUserId`. |
| `GrantedByUserId` | integer | Required foreign key to granting user. |
| `GrantedAtUtc` | datetime | Required UTC timestamp. |
| `RevokedAtUtc` | datetime, nullable | Null means active; setting it records explicit revocation without erasing history. |

A database check constraint and service validation require exactly one target. Active
shares are considered independently from project membership. Removing project membership
removes membership-derived access but does not revoke an active direct or department
share.

### DocumentActivity

Represents an auditable document action, including actions whose document row is later
permanently deleted.

| Field | Type | Rules |
|---|---|---|
| `DocumentActivityId` | integer | Primary key. |
| `DocumentId` | integer, nullable | Foreign key to `Document`; set null after permanent deletion so the deletion activity survives. |
| `ActorUserId` | integer, nullable | User who performed the action; nullable only for a defined system action. |
| `ActionType` | text or enum-backed value | Upload, Download, Preview, Replace, Delete, Share, or AccessReview. |
| `DocumentTitleSnapshot` | text | Maximum 255 characters; preserves report context after deletion. |
| `OccurredAtUtc` | datetime | Required UTC timestamp; reporting filter field. |
| `Details` | text, nullable | Safe, non-sensitive summary; maximum 1,000 characters; must not contain file contents or secrets. |

Activity rows remain reportable for 12 months. Administrator reports accept an inclusive
UTC date range within the 12-month window and aggregate by action, file type, uploader,
and access pattern.

### Existing Notification

The feature reuses the existing `Notification` entity and adds document-specific values
to its notification type set:

- `DocumentShared`: informs a direct or department-share recipient.
- `DocumentAddedToProject`: informs eligible project members.

Notifications reference the recipient user and follow the existing unread, priority, and
created-date behavior. A failed notification write must not grant additional document
access; the service reports the notification failure separately from a successful file
operation where the workflow permits.

## Relationships

- `User` 1-to-many `Document` through `UploaderId`.
- `Project` 1-to-many `Document` through nullable `ProjectId`.
- `TaskItem` 1-to-many `Document` through nullable `TaskId`; when present, `Document.ProjectId` must equal `TaskItem.ProjectId`.
- `Document` 1-to-many `DocumentTag`, with dependent cleanup on permanent document deletion.
- `Document` 1-to-many `DocumentShare`; revoked rows remain for audit and duplicate-grant prevention.
- `Document` 1-to-many `DocumentActivity`, with `DocumentId` set null after permanent deletion.
- `Document` access also derives from existing `ProjectMember`, `Project.ProjectManagerId`, `User.Role`, `User.Department`, and active `DocumentShare` relationships.

## Authorization Rules

| Operation | Allowed actors |
|---|---|
| Upload personal document | Any signed-in employee. |
| Upload project document | Assigned project member, project manager, team lead under existing project rules, or administrator. |
| List/search/preview/download | Document owner, permitted project member, project manager, eligible team lead, administrator, or active explicit share recipient. |
| Edit metadata or replace file | Document owner; project manager for a project document; administrator. |
| Delete | Document owner; project manager for a project document; administrator. |
| Share | Document owner; administrator; project manager for a project document where the existing project rules grant management. |
| View audit reports | Administrator. |

All rules execute in the service before metadata or file bytes are returned. Missing and
unauthorized document requests use the same not-found behavior at the access boundary.

## Indexes and Query Rules

- `Document(UploaderId, UploadedAtUtc)` supports My Documents and recent uploads.
- `Document(ProjectId, UploadedAtUtc)` supports project document lists.
- `Document(TaskId)` supports task attachments.
- `Document(IsAvailable, UploadedAtUtc)` prevents incomplete candidates from list queries.
- `DocumentShare(TargetUserId, RevokedAtUtc)` and `DocumentShare(TargetDepartment, RevokedAtUtc)` support active share checks.
- `DocumentTag(TagText, DocumentId)` supports tag search.
- `DocumentActivity(OccurredAtUtc, ActionType)` supports date-range reports.
- Existing `User(Department)` data is used for team resolution; a standalone team table is not introduced.

Search applies authorization predicates before returning rows and searches title,
description, tags, uploader display name, and project name. Query results are bounded to
permitted records and the acceptance performance target is validated with up to 500
records; a full-text search engine is not required for the initial training scope.

## Lifecycle Transitions

```text
Selected
  -> Rejected (missing metadata, unsupported type, over size, unsafe, indeterminate, or storage failure)
  -> StoredCandidate -> Scanned
       -> Rejected (scanner failure or unsafe result; candidate file is removed)
       -> Available (final private path and metadata row are committed)

Available
  -> Replaced (new candidate validates and scans; current file remains until commit)
  -> Deleted (file and metadata are permanently removed; activity snapshot remains)
```

For replacement, the candidate file is validated, stored privately, scanned, and committed
before the old file is removed. Compensation removes the candidate if database persistence
fails. No user-facing operation can return a path or row for a rejected candidate.
